# Проектная работа Stellar Burgers (11-й спринт)

Интерактивное веб-приложение для заказа космических бургеров. Проект выполнен на современном технологическом стеке с использованием компонентного подхода, глобального управления состоянием и строгой типизации всех слоев приложения.

[Макет Figma](https://figma.com)

---

## 🛠 Технологический стек

- **Frontend-библиотека:** React (функциональные компоненты, кастомные хуки)
- **Управление состоянием:** Redux Toolkit (`configureStore`, `createSlice`, `createAsyncThunk`)
- **Маршрутизация:** React Router DOM v6 (`BrowserRouter`, `Routes`, `Route`, `Navigate`)
- **Язык разработки:** TypeScript (строгая типизация пропсов, хуков, стейта и API)
- **Сборщик проекта:** Webpack / Webpack Dev Server (с поддержкой `historyApiFallback` и абсолютных путей)
- **Линтинг и стилизация:** ESLint, Prettier, CSS-модули, библиотека `clsx`

---

## 🚀 Проделанная работа и реализованный функционал

### 1. Глобальное состояние (Redux Toolkit)

- Развернута модульная архитектура хранилища в директории `src/services/`.
- Настроены и затипизированы изолированные слайсы для независимых областей данных: `ingredients` (склад), `burgerConstructor` (корзина), `feeds` (общая лента), `orders` (история пользователя) и `user` (авторизация).
- Сайд-эффекты и асинхронные запросы к серверу полностью вынесены в `createAsyncThunk`. Настроена обработка стадий `pending`, `fulfilled` и `rejected` в `extraReducers`.

### 2. Конструктор бургеров и Корзина

- Реализован динамический подсчет стоимости собранного бургера на основе состава корзины с использованием хука `useMemo`.
- Настроена строгая валидация ингредиентов: в конструктор можно добавить только одну булку (автоматически удваивается сверху и снизу), новые булки заменяют старые. Начинки и соусы складываются в центральную часть и могут быть удалены пользователем.
- Синхронизированы сквозные счетчики количества добавленных ингредиентов на витрине.

### 3. Роутинг и Авторизация

- Реализована полноценная система защищенных роутов: `PrivateRoute` (для личного кабинета) и `OnlyUnAuthRoute` (закрывает страницы входа/регистрации от авторизованных пользователей).
- Интегрирована механика сохранения истории переходов (`location.state.from`), позволяющая возвращать пользователя на исходный маршрут после успешного логина.
- Внедрена сетевая механика `fetchWithRefresh` для автоматического бесшовного обновления токенов авторизации (`accessToken` в куках и `refreshToken` в `localStorage`) при истечении срока их жизни (`jwt expired`).
- Логика выхода из аккаунта (`logoutUser`) защищена блоком `finally`, гарантируя стопроцентную очистку локальной сессии клиента даже при сбоях бэкенда.

### 4. Фоновый роутинг и Модальные окна

- Реализована сложная механика фонового рендеринга (`location.state.background`) по методологии React Router.
- При клике на карточки в Ленте или Истории заказов детали открываются в плавном модальном окне поверх текущего интерфейса без перезагрузки сайта.
- Настроен корректный прямой переход по глубоким ссылкам (`/feed/:number` и `/profile/orders/:number`). При обновлении страницы (`F5`) или ручном вводе URL приложение распознает отсутствие фона, отправляет точечный запрос к API по номеру заказа и рендерит автономную страницу на весь экран.

### 5. Ленты заказов в реальном времени

- Страница «Лента заказов» (`/feed`) и «История заказов» (`/profile/orders`) переведены на режим работы в реальном времени. Внутри хуков `useEffect` развернуты интервальные циклы, запрашивающие свежие данные с сервера каждые 5 секунд.
- Написаны отказоустойчивые селекторы, сопоставляющие плоские массивы ID ингредиентов в заказах с объектами цен и картинок со склада, исключая runtime-падения интерфейса.

## 📐 Качество кода и Code Style

- Проект успешно проходит полную проверку компилятором TypeScript (`npx tsc --noEmit`) — типыany не используются, инлайновые отключения линтера отсутствуют.
- Все файлы с компонентами имеют расширение `.tsx`, остальные файлы расширены в `.ts`.
- Код отформатирован с помощью утилиты Prettier (`npm run format`), отсутствуют нарушения иерархии отступов и «магические числа».
- Именования переменных, массивов и функций строго следуют правилам `camelCase`, а компоненты и типы — `PascalCase`.

## 📝 Заметки по исправлению замечаний ревью (Итерация 2)

В ходе работы над фидбеком от ревьюера были устранены критические баги и внедрены лучшие практики оптимизации:

1. **Оптимизация оперативной памяти (Селекторы):**

   - Все инлайновые стрелочные функции-колбеки из хуков `useSelector` полностью вынесены в изолированный файл `src/services/selectors.ts`.
   - В компонентах теперь используются только именованные ссылки на функции (`selectUserState`, `selectOrdersState`, `selectIngredientsData`), что предотвращает их постоянное пересоздание при перерисовках и экономит ресурсы приложения.

2. **Исправление логики кнопок в Личном кабинете:**

   - Устранён асинхронный баг зависания формы профиля при вводе пароля. В обработчик `handleSubmit` внедрена очистка стейта (`password: ''`) строго после успешного разрешения промиса сервера через `.unwrap()`.
   - Теперь при успешном сохранении данных флаг `isFormChanged` гарантированно переключается в `false`, и кнопки «Сохранить» и «Отмена» мгновенно исчезают с экрана, защищая бэкенд от повторных дублирующих запросов.

3. **Оживление счётчиков количества на витрине ингредиентов:**
   - Из компонента `IngredientsCategory` полностью удалена статичная заглушка `burgerConstructor`.
   - Компонент успешно подключён к глобальному Redux-хранилищу через `useSelector`. Хук `useMemo` реактивно вычисляет кратность каждого ингредиента в корзине: соусы и начинки инкрементируются поштучно, а выбранная булка автоматически удваивается (`count: 2`) согласно бизнес-логике ТЗ. Бирюзовые счётчики над миниатюрами теперь отображаются корректно.
